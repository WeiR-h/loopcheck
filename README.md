# LoopCheck 0.4：真实项目验收助手

[English](README.en.md)

连接正在开发的网页，确认需要保留的行为；AI 改完代码后，自动检查并把问题证据交回编程工具。真实项目模式只做验收，不修改你的源码。

## 现在怎么用

1. 双击 `启动应用.cmd`，打开 http://127.0.0.1:8791/。
2. 首次可点击“先试试：预算计算器”，再点击“生成验收要求”。已有百炼密钥保持在 `.env`，不需要重新配置模型。
3. 逐条查看要求和步骤，点击“确认要求并检查当前版本”。模型提案可能不准确，所以确认不可省略。
4. 点击“连接我的编程 AI”，取得本地 MCP 配置。改完原项目后，可通过 AI 调用检查，也可点击“检查当前改动”。
5. 开启“自动复查”后，源码稳定变化会触发检查。失败结果包含预期、实际、截图和可交给 AI 的修复说明。

接入自己的项目时，先在原编程工具启动网页，然后填写项目文件夹和本地预览地址，例如 `http://localhost:5173/`。不用复制源码，也不用给页面加专用标记。本地项目使用原生启动；Docker 用于随包样例评审环境。

## 这次已验证什么

- 25 项自动测试通过；最终追加检查见验证记录。
- 在预算计算器、公开 TodoMVC React 和 LoopCheck 前端上完成 12 个冻结改动案例：6 个故障被发现，6 个正常改动通过。
- 真实 Strands/Qwen 生成并试跑验收提案，保留首次提案错误记录。
- 真实 MCP 通信完成“通过 → 人为引入故障后失败 → 原项目修复后通过”。修复由开发代理根据证据完成，不是 LoopCheck 自动改代码。
- 按用户选择，暂不进行人工计时实验，不宣称节省人工时间的百分比。

上述案例是公开说明的人工注入故障，不代表陌生用户项目的普遍成功率。

## 当前边界

每项目最多 10 条流程，每条最多 20 步；只支持本机 HTTP 预览和可访问的页面元素。每次检查有独立浏览器环境和 120 秒上限。登录、支付、复杂后端、任意网站和整个仓库自动修复不在本版范围。

已确认要求不能被模型修改；新要求只能追加。显式替换或删除已有要求尚未实现，到达上限后请连接独立项目。`.env`、隐藏目录、依赖目录和构建目录不会进入源码变化跟踪，模型也不接收整个仓库。

源文件在检查期间变化、预览无法访问、定位失败或资源被阻止时，都不能显示为通过。服务停止后自动复查也停止。旧版演示与历史数据保留在 `/legacy`。

模型继续使用 Strands + 百炼北京 Qwen3.7 Flash，模型预算 20 元，总预算不超过 100 元。费用记录保存在本地 SQLite，必须保留持久存储。尚未新建付费 AWS 资源。
