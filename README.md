# LoopCheck 0.5.0

让 AI 改码后的验收要求能够持续使用。[English](README.en.md)

先保存业务要求，再为已经实现的功能生成检查。新增功能尚不存在时，可以确认要求，但会持续显示“尚未建立检查”；旧检查全部通过也不能掩盖未完成的新要求。

## 开始使用

运行 `install.ps1` 安装环境，在已有 `.env` 中保留百炼北京地域的 `DASHSCOPE_API_KEY`，使用 Strands + `qwen3.7-flash`。模型预算 20 元，总预算 100 元。运行 `启动应用.cmd`，打开 http://127.0.0.1:8791/ 。密钥不要填写到网页或源码中。

1. 先试“购物车开发场景”或“预算计算器”，也可连接自己的项目文件夹和已经启动的本地预览地址。
2. 输入修改目标，生成业务要求。对照原始描述，补充或修改提案，再确认。
3. 点击“为待实现要求生成检查”，查看真实页面上生成的步骤，再确认执行。尚不存在的控件对应的要求保持未覆盖。
4. 让现有编程 AI 修改原项目，点击“检查当前改动”。已有检查重跑不调用模型。
5. 失败时复制完整证据给 AI，修复后复查。也可使用本地 MCP 的三个工具完成证据交接。

已确认要求支持修改、停用并说明原因、恢复和重建检查。每次变更先查看差异，再确认。修改后的要求不会沿用旧通过结论。旧运行显示历史标识；只有全部启用要求有检查且当前版本全部通过，才可接受本次改动。

## 已验证与边界

12 个冻结改动案例全部符合预期；购物车完成“通过 → 未完成 → 发现回归 → 修复后通过”的真实浏览器验证。模型规划四目标最新一轮为 4/4 通过，五轮结果（0/4、1/4、2/4、0/4、4/4）全部保留；完整 35 项测试通过。同一小样例集的调试结果不能保证陌生项目首次生成的步骤正确。请查看 [完整验证记录](docs/验证记录-v05.md)，不要把自动化结果理解为人工效率或市场验证。
